# Trace 文件来源

HiTrace 在设备上创建的 trace 文件使用扩展属性 `user.trace_source`，取值只能是 `system` 或 `user`。
来源用于区分文件的管理策略，不表示采集成功或内容完整。两种来源都在写入内容之前建立；
初始化失败、部分写入失败或进程退出后留存的文件保留已经建立的来源。

## 场景与标签

| 场景 | 来源 |
|---|---|
| 同步 `DumpTrace()`，`outputPath` 为空，创建新快照 | `system` |
| 同步 `DumpTrace()`，显式指定文件或目录，创建新快照 | `user` |
| 显式指定 `/data/log/hitrace` 或 `/data/log/hitrace/` | `user` |
| 异步 `DumpTraceAsync()` 实际落盘 | `system`；接口没有输出路径参数 |
| `CacheTraceOn()` 生成缓存切片 | `system` |
| 缓存经不带输出路径的同步请求转换为快照 | `system` |
| 缓存经显式指定输出路径的同步请求转换为快照 | `user` |
| 缓存经异步请求转换为快照 | `system` |
| `RecordTraceOn()` 默认路径、显式文件或目录 | `user` |
| 录制按大小分片、输出文件被移除后重建 | `user`，每次创建都建立来源 |
| 命令行普通文本、压缩输出文件 | `user` |
| 命令行文本输出被重定向至普通文件 | `user`；终端、管道没有文件标签 |
| 命令行 raw / `--record` 录制 | `user`，沿用录制接口 |
| 命令行后台快照 `--dump_bgsrv` | 按传入快照接口的输出路径是否为空分类 |
| boot trace，包括默认配置、指定路径、递增文件 | `user`；执行时向快照接口传入明确输出路径 |
| 应用自采集 `StartCaptureAppTrace()`，默认或指定路径 | `user` |
| 仅复用已存在的快照 | 保留该文件既有来源，不重新分类 |
| 异步读取阶段、trace marker、仅停止且不输出 | 不创建 trace 文件，无需文件标签 |

来源依据生成模式和请求参数确定，不依据文件最终所在目录或调用进程身份判断。
输出路径范围沿用各接口的校验；本次不扩展支持的目录形式。
已有快照被复用与缓存转换是两种操作：缓存转换会重新设置来源，后续复用该快照不会改回。
历史快照即使使用 `cache_` 开头的自定义文件名，也不会被当作缓存转换；归类依据实际所属列表。
缓存转换仍在原目录重命名，不因此增加复制到请求路径的行为。

## 写入和转换

二进制输出工厂在创建或替换输出 fd 时建立来源，并持有非阻塞独占锁。
锁随 fd 关闭、替换或进程退出释放；时间老化跳过正在持锁的文件。
标签或锁建立失败时终止写入并尝试清理，不把未建立来源的新文件当作成功输出。
文件创建、xattr 和清理不是文件系统原子事务；文件系统异常时清理也可能失败。

缓存转换获取文件锁，按转换请求设置来源，然后重命名。失败的转换不加入结果列表，
也不计入该次结果的文件大小和覆盖时长；重命名失败时尝试恢复缓存的 `system` 来源。
如果仍有其它有效文件，沿用部分结果成功规则；无可返回文件且转换失败时返回写入错误。
转换不刷新 `mtime`。原缓存路径在下一轮容量核对时退出缓存预算。

## 老化边界

`AgeTraceFile()` 仍仅按默认目录、`system` 标签、`mtime`、保留时间及文件锁判断。
转换成 `user` 的快照不再属于该接口的系统时间老化对象。
录制数量/容量清理和缓存容量清理仍按各自策略执行，`user` 不代表文件永不删除。
本规格不批量迁移历史无标签文件，也不处理设备外转换工具创建的派生文件。
